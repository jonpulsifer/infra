The SDK one script tag on each site
<script src="/_/sdk.js"></script>

await kthx.db.set('votes', { optiplex: 3, riptide: 1 })
await kthx.db.get('votes')              // { optiplex: 3, riptide: 1 }
await kthx.db.list('rsvp/')             // [{ key, value }, …]
await kthx.db.del('votes')

await kthx.db.update('votes', v => ({ ...v, riptide: (v?.riptide ?? 0) + 1 }))
                                          // read, change, write — retried if another tab wrote first; v is null for a new key
JSON by key, scoped to the site. There is no schema. There is no connection string. Use update when two tabs write to the same key. get and set can lose a write. A poll is the first thing that most people build.
// each write to the store goes to each open tab; value is null after del
const stop = kthx.db.watch('votes', ({ value }) => render(value))
kthx.db.watch('rsvp/', ({ key, value }) => addRow(key, value))   // a trailing / is a prefix

// or skip the store: a room is a socket with a name
const room = kthx.live.join('cursors')
room.send({ x, y })                                // to each other member of the room
room.on('message', ({ from, data }) => draw(from, data))
room.on('join', peer => ...)
room.on('leave', peer => ...)
room.peers()                                       // the me.id of each member here now
room.leave()
One websocket for each tab. The socket opens on first use and reconnects on its own. watch sends each write in the store to all open tabs and returns a function that stops it. This is the durable path. live.join is for data that must not go to the store: cursors, typing, presence, a game tick. Rooms are scoped to the site.
await kthx.ready
kthx.me.id               // stable for each browser, anonymous, null before ready
Each visitor is anonymous. With me.id, a poll knows that a visitor voted before. The visitor does not log in. The id is a cookie on the site, set on first use.
