The problem

“I wrote a thing. Put it somewhere with a URL.”

Nothing on that list is unsolved. Clusters exist, registries exist, GitOps engines exist, certificates are free. What nobody hands you is the assembly — and the assembly is the work, in full, every single time.

Seven decisions, made by hand, by whoever is holding it. Each one is a place to be quietly wrong for a month.

  1. Write a Dockerfile
  2. Author a Helm release or a Kustomization
  3. Find a hostname
  4. Wire a route
  5. Add a secret
  6. Open a PR, wait for CI, wait for Flux
  7. Read pod logs to find out why it did not come up

The contract

A deploy is three things, pinned

Artifactwhat runs — by digest
Targetwhere it runs
configVersionwhat it reads — by digest

Every part is named by value, not by reference. Nothing in the triple means “latest”.

deploy 2 · artifact files·sha256:1d7ea… · target bluenose/static · configVersion sha256:4f53cda1…

Identity, kept separate from placement

Source → Build → Artifact → Deploy. One Build makes one Artifact; one Artifact goes to many Deploys. What was built never learns where it went — and that one separation is what the rest of this deck is downstream of.

Two authored nouns

A human writes an App and a Component. Build, Artifact and Deploy are produced, never typed.

04 / 06

The second contract

Every outside thing sits behind a seam, and none of them is the architecture

A seam is a place behaviour can be swapped without editing at that place. One implementation would leave a seam hypothetical; every one of these has at least two.

SeamAdapters today
BuildGitHub Actions · Cloud Build · microVM pool · in-cluster Job
DeployKubernetes · Cloud Run · static hosting
DeliveryFlux HelmRelease · Argo Application
Config storeSecret Manager · 1Password · HTTP
Datastorecloud project · cluster

Flux is an adapter, not the architecture

A Target declares which operator drives it, and Spindrift writes that operator's own object. Both flavours end at the same status type and nothing above them branches.

What a seam is worth, measured once

A whole fourth way of building — a microVM pool on a machine this process cannot reach, calling in the opposite direction — arrived as one row in a list. Everything above the seam was already written.

05 / 06

Two more boundaries, drawn the same way

Who may reach it, and where authority stops

Reach and auth are fields, not policy

reach and auth sit in desired state beside the image and the config, so they are pinned into the deploy like everything else. A Target declares which reaches it can authenticate — so auth decides where you are allowed to deploy, before a build is dispatched.

Internalcluster only
Privatean RFC1918 address
Publicthrough the tunnel

Private is the default. Nothing becomes reachable because somebody forgot a field.

It cannot create what it deploys into

Spindrift holds delegated write access to contents — a release object in one namespace, an App inside one pre-provisioned project. It holds nothing that can create a cluster, a project, a VPC, a tunnel or a signing key. When a prerequisite is missing it writes the infrastructure code that would clear it and opens that as a pull request.

The refusal

A contract is allowed to disqualify a backend

Static hosting refuses auth: proxy outright — there is no non-bypassable origin to put a boundary in front of, so the placement is rejected rather than shipped with a caveat. A guarantee that quietly degrades is not a guarantee.

06 / 06

Consequences, not features

Four things nobody had to build

Rollback

An older triple

Not a rebuild. Retention depth is 10, which is therefore also rollback depth.

Two runtimes

No new concept

An artifact is image or files. Kubernetes, Cloud Run and static hosting are the same triple with a different where.

Concurrency

Impossible, not racy

The triple is taken under a locking read against the transactional Component@Target.desired row.

Config

Cannot drift underneath

Pinned by digest into the deploy — so a running deployment reads what it was deployed with.

This page is its own acceptance evidence: uploaded as an archive, built into a files artifact, served at a URL by the thing it describes.

Contract one · what a deployment is

A deploy is three things, pinned

Artifact, Target, configVersion — every part named by value, so nothing in a deployment can mean “latest”.

Why by value, and what it buys
Artifactwhat runs — by digest
Targetwhere it runs
configVersionwhat it reads — by digest

deploy 2 · artifact files·sha256:1d7ea… · target bluenose/static · configVersion sha256:4f53cda1…

A real row off the running installation. That line is the deployment — reproducing it needs nothing that could have moved since. Rollback is therefore an older row rather than a rebuild; concurrency is a locking read against Component@Target.desired, so a racing deploy is impossible rather than unlikely; and config cannot drift underneath a running workload.

Contract two · where the outside plugs in

Five seams, and none of them is the architecture

Build, deploy, delivery, config store, datastore — each swappable without editing at the place it is used, and each already has at least two implementations.

The seams, and what one is worth
SeamWhat varies across itAdapters today
Buildwhere the artifact is producedGitHub Actions · Cloud Build · microVM pool · in-cluster Job
Deploywhat runtime receives itKubernetes · Cloud Run · static hosting
Deliverywhich operator drives itFlux HelmRelease · Argo Application
Config storewhere the value of record livesSecret Manager · 1Password · HTTP
Datastorewhere a Target's state livescloud project · cluster

Flux is an adapter, not the architecture

A Target declares which operator drives it, and Spindrift writes that operator's own object. Both flavours end at the same status type and nothing above them branches.

The seam that runs backwards

A microVM pool on a machine this process cannot open a connection to at all — the far side long-polls in. Every instinct says that needs a new concept; it needed a row in a list. That is the test a contract passes or fails.

04 / 05

Contract three · reach, and the edge of authority

Who may reach it is part of the contract

Reach and auth are fields in desired state, so a Target that cannot authenticate a reach is excluded before a build is dispatched — and Spindrift cannot create the thing it deploys into, so it opens a pull request instead.

The three reaches, the refusal, and the boundary
Internalcluster only
Privatean RFC1918 address — the record type is the boundary
Publicthrough the tunnel

Private is the default. Nothing becomes reachable because somebody forgot a field.

A filter on the route, not a library in the app

An auth: proxy Component gets an ExternalAuth filter on its HTTPRoute, enforced by a proxy the platform owns and Spindrift never installs. An App cannot opt itself out of its own edge.

The refusal

It is allowed to disqualify a backend

Static hosting refuses auth: proxy outright — no non-bypassable origin exists to put a boundary in front of. A guarantee that quietly degrades is not a guarantee.

Contents, never the container

It holds nothing that can create a cluster, project, VPC, tunnel or signing key. Missing prerequisite → it writes the Terraform and opens a PR; a human merges, the apply bot applies, a standing check turns the row green.

reach: private · auth: proxy → AUTH_UNSUPPORTED excludes every Target that cannot authenticate at that reach, before a build is ever dispatched
